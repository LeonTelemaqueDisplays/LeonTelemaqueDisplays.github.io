breakage_by_tier.sql, CTEnot yet run
-- Breakage rate by tier: the share of points issued to members
-- in a given tier that are never redeemed (expired or dormant).
-- Same "obscured value" pattern as a gacha pity counter --
-- members with no status-driven reason to stay engaged
-- let value evaporate silently.
WITH tier_points AS (
  SELECT
    h.tier,
    SUM(CASE WHEN t.txn_type = 'earn'   THEN t.points ELSE 0 END) AS points_earned,
    SUM(CASE WHEN t.txn_type = 'redeem' THEN t.points ELSE 0 END) AS points_redeemed,
    SUM(CASE WHEN t.txn_type = 'expire' THEN t.points ELSE 0 END) AS points_expired
  FROM point_transactions t
  JOIN tier_status_history h
    ON t.member_id = h.member_id
   AND t.txn_date BETWEEN h.effective_date AND h.expiry_date
  GROUP BY h.tier
)
SELECT tier, points_earned, points_redeemed, points_expired,
  ROUND(100.0 * points_expired / NULLIF(points_earned,0), 1) AS breakage_rate_pct
FROM tier_points ORDER BY breakage_rate_pct DESC;

cumulative_breakage.sql, window functionnot yet run
-- Cumulative breakage by tier, month over month, plus each
-- month's breakage-rank across tiers. Demonstrates the same
-- "value evaporates quietly" pattern as a running pity counter
-- that nobody is watching until it's too late.
WITH monthly_expiry AS (
  SELECT h.tier, strftime('%Y-%m', t.txn_date) AS month,
    SUM(t.points) AS points_expired_month
  FROM point_transactions t
  JOIN tier_status_history h ON t.member_id = h.member_id
  WHERE t.txn_type = 'expire'
  GROUP BY h.tier, month
)
SELECT tier, month, points_expired_month,
  SUM(points_expired_month) OVER (
    PARTITION BY tier ORDER BY month
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS cumulative_expired,
  RANK() OVER (PARTITION BY month ORDER BY points_expired_month DESC) AS rank_in_month
FROM monthly_expiry ORDER BY tier, month;

Why this sits next to Genshin Impact, not just other loyalty programs

A pity counter and a status ladder solve the same design problem: how do you keep someone spending toward a reward whose exact value they can't see? Genshin's soft/hard pity hides the true odds behind a counter that only becomes legible after dozens of pulls. Aeroplan's SQC ladder does the same thing with money instead of pulls, the jump from 25K to Super Elite (125,000 SQC) isn't priced anywhere on Aeroplan's site in dollars, only in credits.

The breakage data makes the parallel sharper. In both systems, the people who understand the mechanism best extract close to full value. Everyone else pays the "obscured value tax": in Genshin it's players who quit pulling right before soft pity; in Aeroplan it's the ~84% of the member base with no status who let points expire because there was never a status deadline forcing them to look at the balance.

This is the same argument made on the game-systems side of this portfolio in Mid-Loop Engagement Architecture and Economy Architecture, reward pacing, scarcity, and threshold design aren't cosmetic differences between industries. They're the same three levers, priced in different currencies.

The strongest objection to this framing

No one spends real money for a chance at Aeroplan status the way a player spends real money for a chance at a 5★ pull. SQC is earned through purchases most members would make anyway, flights, a co-branded card, everyday spend. By that logic, breakage isn't extraction, it's just forgetfulness, and the gacha comparison is a stretch.

That objection holds cleanly for members who never intended to chase status, most of the base, and most of the breakage. It holds less well for the tier-chasing minority: the query results above show they are making deliberate incremental decisions (which card, which route, which partner redemption) specifically to clear a threshold whose dollar value Aeroplan never publishes. For that group the mechanism is closer than it first looks, informational asymmetry doing the same work a hidden pull-rate does in a gacha system, just denominated in credits instead of pulls.
