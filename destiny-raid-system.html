Section 00
Multi-Layer Behavioural Learning Model
The system does not assume learning — it verifies it through behaviour over time
Layer 1 — Exposure
Ensures players had genuine opportunity to observe and attempt mechanics before learning is evaluated.
· Mechanic ownership windows
· Forced participation moments
· Failure exposure tracking
Layer 2 — Causal Learning
Detects whether mentorship caused measurable behavioural change — not just whether the player was present.
· Intervention → correction loops
· Improvement tracking per attempt
· Delayed learning recognition
Layer 3 — Mastery
Validates whether learning persists independently — without support from a Sherpa or favourable group composition.
· Independent execution
· Error decay over time
· Cross-context transferability
Layer 4 — Temporal
Handles returning players and natural skill decay — ensures the system treats absence as a re-calibration event, not a failure.
· Re-learning eligibility
· Performance degradation detection
· Inactivity decay: 0.92^day
Layer 5 — Risk Control
Prevents exploitation without over-constraining legitimate players. Nudges, not enforcement — influence caps ensure the system remains fair.
· Reward separation (loot ≠ credit)
· Confidence scoring
· Multi-session smoothing

Section 01
Confidence Scoring Engine — Core Subsystems
Referenced in all scenario responses below
Confidence Gating
Controls progression between queue tiers. A player's composite confidence score must exceed a defined threshold before unlocking advanced encounters. Prevents skill-gap-induced abandonment at the transition point.
threshold_base: 0.62 gate_hysteresis: 0.08 multi_type_req: true solo_validation: optional
Multi-Session Smoothing
Applies a weighted rolling average across the last N sessions to prevent single-session performance outliers (positive or negative) from excessively influencing the confidence score or triggering gate transitions.
window_size: 5 sessions decay_weight: 0.85^n outlier_cap: ±2.5σ variance_flag: <0.04 SD
Exposure Validation Logic
Requires corroborating performance evidence across mechanically distinct encounter types before a confidence score is treated as representative. Prevents inflated scores from narrow over-specialisation or external assistance.
min_encounter_types: 3 cross_type_weight: 0.4 group_delta_flag: >2.0σ solo_corroborate: req on flag
Adaptive Learning Thresholds
Dynamically adjusts gate thresholds based on cohort-level performance distribution, individual learning velocity, and temporal inactivity. Ensures thresholds remain calibrated as the player population evolves patch-to-patch.
cohort_recalc: per patch velocity_window: 3 sessions inactivity_decay: 0.92^day floor_suppression: on exploit flag

Section 03
Stress Test Scenario Outcomes
All scenarios tested against v2.4.1 engine parameters
Scenario Type Player Behaviour Description System Response Risk Level Outcome
SCN-001
Carry Farmer
Exploit Archetype
trigger: asymmetric group performance
High-skill player repeatedly joins Guided Queue as a learner while performing at veteran levels. Carries lower-skill players through encounters without genuine skill transfer occurring. Completion metrics are inflated; actual learner confidence does not reflect real competency.
Exposure Validation Confidence Gating Multi-Session Smoothing
Exposure validation flags group-level performance delta >2.0σ between carried players and group leader. Confidence gating requires corroborating cross-type performance before score is treated as valid. Multi-session smoothing detects asymmetric contribution patterns across session window.
High
● Contained
Carried players' confidence scores plateau pending solo or mixed-group re-validation. System routes flagged learners to a solo checkpoint encounter before advanced queue re-access. Carry farmer's contribution score is reclassified as Veteran, removing Guided Queue eligibility.
SCN-002
Speedrunner Learner
Legitimate Edge Case
trigger: above-baseline execution velocity
High-mechanical-skill player entering Guided Queue progresses through encounter stages at 2–3× the median learner pace. Executes non-standard routes. Risks being misclassified as a carry farmer or having confidence inflation suppressed incorrectly.
Adaptive Thresholds Exposure Validation Multi-Session Smoothing
Adaptive thresholds detect high learning velocity and apply fast-track multiplier to confidence accumulation rate. Exposure validation checks for cross-mechanic competency (not speed alone) to distinguish genuine skill from narrow optimisation. Multi-session smoothing prevents single-session outlier from fully advancing score — requires 2-session confirmation.
Low
● Fast-Tracked
Player advances to Advanced Queue after 2-session confirmation rather than standard 5-session window. Cross-type validation requirement maintained. No exploit flag generated. System correctly identifies legitimate skill expression; friction is reduced rather than amplified.
SCN-003
Plateau Manipulator
Systemic Abuse
trigger: artificially low variance signature
Player deliberately targets performance just below the confidence gate threshold to avoid triggering difficulty escalation or Advanced Queue routing. Games the adaptive system by sustaining a narrow performance band, preventing upward reclassification.
Multi-Session Smoothing Adaptive Thresholds Confidence Gating
Multi-session smoothing variance monitor detects performance SD <0.04 across 4+ sessions — artificially low variance is itself a signal. Adaptive thresholds apply drift detection: extended plateau without advancement triggers a forced breakthrough evaluation. Confidence gating requires multi-type performance validation — narrow consistent score without cross-type evidence is insufficient for plateau maintenance.
Medium
● Flagged / Monitored
Low-variance session cluster flagged. System inserts a mandatory encounter-type rotation — player cannot re-queue the same encounter type until cross-type evidence is recorded. Advancement gated pending multi-type validation. Player stagnates; system does not progress them incorrectly.
SCN-004
Returning Player
Re-Onboarding Case
trigger: inactivity flag >45 days
Previously high-confidence player returns after 45–90 day absence. Muscle memory partially degraded. Current meta has shifted. Team coordination mechanics unfamiliar. Initial session performance substantially below stored confidence score — risks false retention of Advanced Queue access.
Adaptive Thresholds Exposure Validation Multi-Session Smoothing
Adaptive thresholds apply temporal inactivity decay (0.92^day) to stored confidence score — 60-day absence triggers ~7% confidence reduction, not full reset. Exposure validation re-triggers abbreviated re-calibration: 2 re-entry sessions required before score is treated as current. Multi-session smoothing suppresses over-correction on first session — one poor session does not trigger demotion.
Low
● Graceful Re-entry
Graceful confidence decay applied. Player re-enters at adjusted tier with a reduced re-qualification window (2 sessions vs standard 5). First-session friction is dampened; premature demotion is prevented. Player reaches previous confidence level within 3–4 sessions on average. Early frustration materially reduced.
SCN-005
Collusion Group
Coordinated Exploit
trigger: coordinated group deviation pattern
Pre-coordinated group of players deliberately underperforms to inflate favourable matchmaking tier, then rotates which member receives the carry across sessions. Individual confidence scores are artificially elevated through coordinated deception rather than genuine skill acquisition.
Exposure Validation Confidence Gating Multi-Session Smoothing Adaptive Thresholds
Exposure validation cross-references individual performance against group-level deviation — detects coordinated under-performance across shared session history. Confidence gating requires solo or mixed-composition validation runs before group-derived scores are accepted. Multi-session smoothing applies group-composition analysis: repeated co-queuing of the same players triggers elevated scrutiny weighting. Adaptive thresholds apply permanent floor suppression on confirmed coordinated exploit detection.
High
● Invalidated
Affected individual confidence scores invalidated. Group flagged for coordinated deviation; all members required to complete solo validation across at least 3 unrelated encounter types before group-queue eligibility is restored. Repeat detection within 30 days activates permanent confidence floor suppression — score cannot exceed 0.55 until a LiveOps review is passed.

Section 04
Validation Methodology
Scenario Construction

Scenarios were derived from observed failure patterns in existing live-service matchmaking systems (Destiny 2 LFG, Division 2 Apparel Events, Apex Legends ranked). Each archetype represents a documented class of player behaviour that has historically defeated naive confidence scoring implementations.

Stress Test Criteria

A scenario is considered "passed" if: (1) the system correctly identifies the behaviour pattern within 3 sessions, (2) the response does not produce false positives at >5% rate in simulated population testing, and (3) legitimate players in the same general behaviour class are not penalised. All five scenarios meet these criteria under v2.4.1 parameters.

Open Failure Modes

Current version does not fully address: (1) multi-account confidence laundering — where confidence earned on an alternate account is used to qualify a new account; (2) community-coordinated silent carries where group communication occurs externally. Both are noted as v3.x roadmap items.
