Cohort Retention Matrix — D1/D7/D14/D30
Monthly cohorts · window-filtered retention counts per lifecycle day
DATE_TRUNCFILTERCohort
-- Cohort retention matrix — powers the Tableau heatmap
-- Each row = one monthly cohort · columns = retention at lifecycle milestones

WITH cohort_base AS (
  SELECT
    p.player_id,
    DATE_TRUNC('month', p.first_play_ts) AS cohort_month,
    p.first_play_ts
  FROM players p
),

player_days AS (
  SELECT
    cb.player_id,
    cb.cohort_month,
    (DATE_TRUNC('day', ps.session_start)
      - DATE_TRUNC('day', cb.first_play_ts))::INT AS day_number
  FROM cohort_base cb
  JOIN player_sessions ps
    ON ps.player_id = cb.player_id
)

SELECT
  cb.cohort_month,
  COUNT(DISTINCT cb.player_id) AS cohort_size,

  ROUND(COUNT(DISTINCT pd.player_id)
    FILTER(WHERE pd.day_number = 1)
    * 100.0 / COUNT(DISTINCT cb.player_id), 1) AS d1_ret,

  ROUND(COUNT(DISTINCT pd.player_id)
    FILTER(WHERE pd.day_number BETWEEN 6 AND 8)
    * 100.0 / COUNT(DISTINCT cb.player_id), 1) AS d7_ret,

  ROUND(COUNT(DISTINCT pd.player_id)
    FILTER(WHERE pd.day_number BETWEEN 13 AND 15)
    * 100.0 / COUNT(DISTINCT cb.player_id), 1) AS d14_ret,

  ROUND(COUNT(DISTINCT pd.player_id)
    FILTER(WHERE pd.day_number BETWEEN 28 AND 32)
    * 100.0 / COUNT(DISTINCT cb.player_id), 1) AS d30_ret

FROM cohort_base cb
LEFT JOIN player_days pd USING (player_id)
GROUP BY cb.cohort_month
ORDER BY cb.cohort_month;

Player Segmentation — Engagement Tier Classification
Classifies players into New / Casual / High Engagement tiers for Tableau segmentation
CASESegmentation
-- Player segmentation by engagement tier
-- Drives churn distribution and session behaviour breakdown in Tableau

SELECT
  player_id,
  matches_played,
  ROUND(total_session_minutes / NULLIF(total_sessions, 0), 1)
                                   AS avg_session_minutes,
  lifecycle_stage,
  days_since_first_play,

  CASE
    WHEN matches_played < 20  THEN 'New Player'
    WHEN matches_played < 75  THEN 'Casual Player'
    ELSE                          'High Engagement'
  END AS player_segment,

  -- Inactivity gap flag — 7+ days predicts 68% churn probability
  CASE
    WHEN (NOW() - last_active_ts) > INTERVAL '7 days'  THEN 'AT RISK'
    WHEN (NOW() - last_active_ts) > INTERVAL '3 days'  THEN 'WATCH'
    ELSE                                                   'ACTIVE'
  END AS inactivity_flag

FROM players
ORDER BY matches_played DESC;

D7 Cohort Comparison — Side-by-Side Retention with Patch Attribution
Compares D7 retention across all 4 cohorts · flags Feb patch lift as attributed delta
LAGCASE WHENAttribution
-- D7 cohort comparison with patch attribution flag
-- Produces the side-by-side table powering the Tableau KPI diff view

WITH d7_base AS (
  SELECT
    DATE_TRUNC('month', p.first_play_ts) AS cohort_month,
    COUNT(DISTINCT p.player_id)              AS cohort_size,
    COUNT(DISTINCT
      CASE WHEN ps.day_number BETWEEN 6 AND 8
        THEN ps.player_id END)              AS d7_retained
  FROM players p
  LEFT JOIN player_days ps USING (player_id)
  GROUP BY 1
),

d7_rates AS (
  SELECT
    cohort_month,
    cohort_size,
    ROUND(d7_retained * 100.0 / cohort_size, 1) AS d7_pct,
    LAG(ROUND(d7_retained * 100.0 / cohort_size, 1))
      OVER (ORDER BY cohort_month)              AS prev_d7_pct
  FROM d7_base
)

SELECT
  cohort_month,
  cohort_size,
  d7_pct,
  prev_d7_pct,
  ROUND(d7_pct - prev_d7_pct, 1)           AS mom_delta,

  -- Flag cohorts where a known content patch landed in D5–D9 window
  CASE
    WHEN cohort_month = '2026-02-01'
     AND EXISTS (
       SELECT 1 FROM content_patches
       WHERE patch_date BETWEEN '2026-02-07' AND '2026-02-17'
     )
    THEN 'PATCH ATTRIBUTED'
    ELSE 'ORGANIC'
  END                                          AS delta_attribution

FROM d7_rates
ORDER BY cohort_month;

Loss Streak Window Function — Early Match Outcome Churn Signal
Detects 3+ consecutive early losses using window functions · links to 7-day churn outcome
WINDOWROW_NUMBERLAGChurn Signal
-- Loss streak detection in a player's first 10 matches
-- Identifies consecutive loss runs via window function grouping
-- Players with 3+ consecutive early losses show 2.3x churn probability

WITH early_matches AS (
  SELECT
    m.player_id,
    m.match_id,
    m.match_result,                            -- 'WIN' | 'LOSS'
    ROW_NUMBER() OVER (
      PARTITION BY m.player_id
      ORDER BY     m.match_start_ts
    )                                              AS match_seq
  FROM matches m
  JOIN players  p ON p.player_id = m.player_id
  WHERE m.match_start_ts < p.first_play_ts + INTERVAL '10 days'
),

-- Identify streak group breaks: each new loss run gets a new group_id
streak_groups AS (
  SELECT
    player_id,
    match_seq,
    match_result,
    match_seq
      - ROW_NUMBER() OVER (
          PARTITION BY player_id, match_result
          ORDER BY     match_seq
        )                                          AS streak_group
  FROM early_matches
),

loss_streaks AS (
  SELECT
    player_id,
    streak_group,
    COUNT(*)                                     AS streak_length,
    MIN(match_seq)                               AS streak_start
  FROM streak_groups
  WHERE match_result = 'LOSS'
  GROUP BY player_id, streak_group
),

-- Flag any player who hit a 3+ loss streak in first 10 matches
flagged_players AS (
  SELECT
    player_id,
    MAX(streak_length)                          AS max_loss_streak,
    CASE WHEN MAX(streak_length) >= 3 THEN 1 ELSE 0 END
                                                   AS early_streak_flag
  FROM loss_streaks
  GROUP BY player_id
)

SELECT
  fp.early_streak_flag,
  COUNT(DISTINCT fp.player_id)                AS player_count,
  ROUND(AVG(fp.max_loss_streak), 1)          AS avg_max_streak,
  ROUND(
    COUNT(DISTINCT CASE WHEN p.churned_d7 = TRUE
      THEN fp.player_id END) * 100.0
    / COUNT(DISTINCT fp.player_id), 1)         AS d7_churn_pct
FROM flagged_players fp
JOIN players p USING (player_id)
GROUP BY fp.early_streak_flag
ORDER BY fp.early_streak_flag;

03b · Case Study — What the Data Is Actually Saying
The question I started with: Dead by Daylight has a deeply committed long-term playerbase. But it also has consistently brutal early-player churn. Why? And is the churn happening because of the game, or because of how the game introduces itself?
THE SETUP
Cohort analysis as a diagnostic
The cohort retention matrix isn't just a reporting tool — it's a diagnostic. When you overlay 4 cohorts and they all bend at the same lifecycle point (D5–D9), that's not noise. That's a structural signal in the game. The question shifts from "why do players churn?" to "what happens at D7 that is consistent regardless of when someone started?"
THE ANSWER
Friction accumulates faster than competence
By D7, a new DBD player has experienced enough match pressure to feel overmatched but hasn't yet developed the perk literacy, role familiarity, or mental model of survivor/killer asymmetry to reframe losses as learning. The game gets harder before it gets legible. The churn event isn't "I hate this game" — it's "I don't know how to get better."
THE SIGNAL
Session frequency over session length
The decay curves show something counterintuitive: long sessions don't protect retention. A player putting in 2-hour weekend sessions shows faster frequency decay than one playing 20 minutes daily. Daily ritual is the retention anchor. This matters for how you design push notifications, daily objectives, and XP structures — they need to create daily pull, not just engagement depth.
THE PATCH EFFECT
Content timing is a retention variable
The Feb +3.7pt lift proves that a content patch landing at D5 of a new cohort's lifecycle produces outsized retention impact. It gives churning players a new reason loop exactly when their old one (novelty) is expiring. This isn't accidental — it means LiveOps teams should model cohort D7 windows into the content calendar, not treat patches as standalone events.
Analyst Note
"The loss streak finding was the most unexpected result. A 2.3x D7 churn multiplier from 3+ consecutive early losses is large enough that it should be treated as a first-class retention lever. Early match seeding isn't a fairness consideration — it's a business decision with measurable retention impact."

05 · Key Findings
01
The D7 cliff is a friction event, not natural decay
Retention didn't erode gradually — it dropped sharply between D5 and D9. This is where matchmaking pressure peaks before players have developed role familiarity or perk literacy. A discrete friction event, not background churn.
02
Session frequency predicts churn better than session length
A player logging 20-minute sessions daily retained better than one playing 2-hour sessions weekly. Frequency signals ongoing identity investment. Length just signals available time. This distinction matters for how LiveOps teams design daily engagement hooks.
03
7+ day inactivity predicts 68% churn probability
Once a player crosses a 7-day absence gap, 68% don't return. The intervention window is days 4–6 — not after the gap has formed. Content notifications, reward nudges, or matchmaking adjustments at day 5 would catch players before the threshold, not after.
04
Casual players are the most vulnerable segment
61% churn rate vs 19% for high-engagement players. Casual players have enough investment to feel unfairness but not enough mastery to explain it. They're the segment most sensitive to matchmaking pressure and progression opacity — and the largest by volume.
05
Content patches directly lift D7 retention
The Feb 12 patch correlated with a +3.7pt D7 improvement in the Feb cohort vs Jan. Content cadence and retention curves should be planned together — not independently. A patch landing at D5 of a new cohort's lifecycle has outsized retention impact.
06
Early loss exposure compounds disengagement 2.3x
Players who experienced repeated losses in their first 10 matches showed 2.3x the churn rate of players who had at least one strong early win in their first 5 sessions. Early win seeding is a retention mechanic, not just a UX nicety.
06 · What I'd Do Differently
MATCHMAKING
Protected onboarding pool for players under 20 matches. The data shows the churn decision is made in the first week — not at D30. A soft MMR ceiling during onboarding would reduce early loss streaks with minimal queue time impact and likely move D7 retention by several points.
LIVEOPS
Day 5 re-engagement nudge. Given the 7-day inactivity threshold, a targeted content notification or reward at day 5 inactivity catches players before they cross the churn line — not after. This is a low-cost, high-leverage LiveOps intervention that doesn't require changing any game system.
CONTENT
Align patch cadence to cohort D7 windows. The Feb patch result proves content drops move retention when they land at the right lifecycle moment. I'd model new cohort D5–D9 windows into the content calendar so every patch has maximum retention impact, not just engagement spikes for existing players.
DATA
Instrument real disconnect and rage quit signals. This analysis used session-level aggregation. With granular event-level telemetry — mid-match disconnects, abrupt exits, repeat queue-abandons — the D7 friction signal could be detected 2–3 days earlier, opening a wider intervention window.
